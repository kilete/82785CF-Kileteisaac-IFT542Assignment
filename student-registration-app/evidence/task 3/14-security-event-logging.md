# Phase 5 Evidence 14: Security Event Logging

Scope: localhost-only security event logging for fictitious IFT 542 lab data.

Architecture:

- Security events are stored in the existing `audit_logs` database table.
- `src/services/auditLogService.js` provides `recordSecurityEvent()`.
- `action` stores the event type.
- `resource` stores safe route, field, role, reason, and hashed identifier details.
- `created_at` is generated by the database with `CURRENT_TIMESTAMP`.
- Logging failures are handled inside the audit service so they do not expose database errors to users.

Implemented event types:

- `authentication_failure`
- `authentication_success`
- `authorization_denied`
- `validation_rejected`
- `csrf_validation_failed`
- `ssrf_destination_rejected`

Sensitive values excluded:

- Passwords
- Password hashes
- Session IDs
- Session cookies
- CSRF tokens
- Authorization tokens
- Database credentials
- Environment secrets
- Complete request bodies
- Uploaded document content
- Full rejected SSRF URLs

Result: PASS for Phase 5 security logging requirements.
